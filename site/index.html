How it works

Three passes. Nothing changes until the audit is done.

  1. 01

    Audit

    Works out your stack and scores ten categories from 0 to 10. Every low score points to a file and line.

  2. 02

    Fix

    Branches to glowup and fixes one category at a time, security first. Builds, tests and commits after each.

  3. 03

    Re-score

    Scores it again with the same rubric and shows both scorecards side by side, plus what the next tier needs.

Ten categories

Scored out of 100. Fixed in this order.

  1. SecurityNo secrets in code, auth on private routes, no injection.
  2. Backend & APIValidated input, real status codes, thin handlers.
  3. DatabaseMigrations, indexes, no queries in loops.
  4. Error handlingCaught at the edges, messages people can act on.
  5. StructureClear folders, no 1,000-line files, no dead code.
  6. Types & qualityTypes on, linter and formatter set up, no any soup.
  7. TestsCore logic and main routes, one command runs them.
  8. DevOpsCI runs lint, tests and build. A health check.
  9. ObservabilityStructured logs, no stray console.log.
  10. UI polishConsistent spacing, loading, empty and error states.
  1. 0–39Vibe Prototype
  2. 40–59Side Project
  3. 60–79Launch-Ready
  4. 80–89Professional
  5. 90–100Production Grade

Usage

Run it in any project.

/glowup

The full run: audit, fix all ten, re-score.

/glowup audit

Just the scorecard and a fix plan. Changes nothing.

/glowup security

Fix one category. Works with any of the ten.

It keeps your stack, never deletes features or commits secrets, and asks first if you have uncommitted changes. Undo a whole run with git branch -D glowup.
