/glowup for Claude Code

Make your vibe-coded app production-ready.

A command that scores your project out of 100 across ten categories, fixes them one at a time starting with security, and then scores it again. Every category it fixes is a separate commit on a glowup branch, so you can review or undo any of it.

01How it works

One command, three passes. It doesn't touch your code until the audit is done and it's working on a new branch.

  1. 1Audit

    Reads your README, config and entry points to work out the stack, then scores ten categories from 0 to 10. Every score under 7 points to the file and line behind it.

  2. 2Fix

    Branches to glowup, then fixes one category at a time, security first. After each one it runs your build, tests and linter, then commits.

  3. 3Re-score

    Scores the project again with the same rubric and prints both scorecards side by side, with what changed and what the next tier needs.

03Usage

/glowupFull run: audit, fix all ten categories in order, re-score.
/glowup auditScorecard plus the ten fixes worth the most, security first. Changes nothing.
/glowup <category>Fixes one category, for example /glowup security, /glowup tests or /glowup ui.

Guardrails

  • If you have uncommitted changes, it asks before it starts. Then it works on a new glowup branch. Outside a git repo, it runs git init and commits what's there first.
  • After each category it runs the build, tests and linter you already have, and fixes anything it broke before moving on.
  • It keeps your stack. No rewrites into a different framework.
  • It never deletes features, changes what the app does, adds paid services or commits secrets.
  • When a fix needs a decision only you can make, like which auth provider to use, it picks the standard free option and tells you.

Undo a whole run with git checkout main && git branch -D glowup.

05Contribute

A new command is one Markdown file and one registry entry. There's no build step: the installers and this page both read the registry.

  1. Write the command

    Create features/<name>.md with a description: line in its frontmatter. Use $ARGUMENTS where the user's input should go.

    ---
description: One line that says what the command does
argument-hint: [optional | args]
---

# Your command

Steps Claude should follow when someone types /your-command.

  2. Register it

    Add an entry to features/features.json. "stable" gets installed; "planned" is only listed here.

    {
  "id": "my-feature",
  "name": "My Feature",
  "command": "my-feature",
  "file": "my-feature.md",
  "summary": "What it does, in a sentence or two.",
  "usage": "/my-feature  ·  /my-feature <arg>",
  "tags": ["tag-one", "tag-two"],
  "status": "stable"
}

  3. Check it

    $ node tools/validate.mjs
OK: 2 feature(s) checked.

    It fails on a duplicate id or command, a missing field or file, or frontmatter without a description.

  4. Open a pull request

    Once it's merged into main, the Pages workflow runs the same check and republishes the site. Anyone who runs the installer again gets the new command.

The full guide is in CONTRIBUTING.md

06Install

The installer reads the registry and copies every stable feature into ~/.claude/commands. Run it again to update. If Claude Code is open, restart it.

Windows PowerShell
irm https://raw.githubusercontent.com/drewguitarist18-lang/glowup/main/install.ps1 | iex
macOS, Linux, Git Bash needs curl and Node.js
curl -fsSL https://raw.githubusercontent.com/drewguitarist18-lang/glowup/main/install.sh | bash

To uninstall, delete ~/.claude/commands/glowup.md.
